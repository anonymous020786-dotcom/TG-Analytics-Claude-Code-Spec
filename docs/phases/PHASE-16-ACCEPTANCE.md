# Phase 16 Acceptance Matrix — Accounts and Sessions (Sign in with Telegram)

Verified on 2026-09-30: unit, integration and API e2e tests, full CI, and the staging edge with the real staging bot token. Design: ADR-017. Identity method: D-021 (owner decision: Telegram only; no email/password).

| Area | Required | Evidence |
|---|---|---|
| FR-AUTH-01 sign-in | Telegram sign-in creates or reuses the account | API e2e: first sign-in creates (`created: true`), later ones refresh the name (1 user row); staging E2E: sign in → `/account` shows name and username → sign out |
| Signature verification | Only Telegram-signed, fresh payloads | `@tga/auth` (22 unit tests): documented data-check-string, HMAC with SHA-256(bot token), tampered/added/removed field, other bot, stale (> 10 min), future `auth_date`, 12 malformed shapes; signature checked before expiry (no oracle). Staging: tampered → 401, stale → 401 |
| Sessions (FR-AUTH-02) | Secure cookies, lifetimes, rotation, revocation | Cookie `__Host-tga_session=…; Path=/; HttpOnly; SameSite=Lax; Max-Age=2592000; Secure` (asserted in e2e and through the staging edge). Only SHA-256 stored (test finds no plaintext token). Idle expiry 7 days, sliding, capped at 30-day absolute (repository and e2e tests). New session on every sign-in, old one revoked (fixation test). Sign out and sign out everywhere. Disabled users lose access |
| CSRF (FR-AUTH-02, T04) | A state-changing request without a CSRF token is rejected | e2e: missing, wrong, other client's token, no pre-session cookie → 403; foreign/missing `Origin` → 403; form-encoded body → 415; pre-login token useless after sign-in (bound to the session). Staging edge: no token / foreign origin → 403 |
| Login CSRF | Attacker cannot sign a victim into the attacker's account | Widget callback mode only (POST + CSRF bound to the `__Host-tga_pre` nonce); redirect (GET) mode not used |
| Open redirects | `?next=` stays on site | `safeNext` unit tests (11 cases incl. `//host`, `/\host`, schemes, control characters); staging: three attack values all land on `/account` |
| Enumeration / logging | Generic failures, no secrets in logs | Every verification failure is the same `401 invalid_login`; the reason is in the security log only, with no payload or hash (asserted); successes audited (`auth.account_created`, `auth.login`, `auth.logout`, `auth.logout_all`) |
| Abuse (T01) | Rate limits | Edge zone `/api/v1/auth/` 10 r/min per IP, burst 20 (provisional); request body limit 16 KB; signature forgery infeasible (no password to guess) |
| Data minimization | Store only what is needed | `users`: Telegram id, first/last name, username. No phone, photo or email. `user_sessions`: token hash, truncated User-Agent, no IP (DATA-POLICY updated) |
| Migration | Schema via migration | `20260930092515_accounts` (users, user_sessions, CHECK constraints incl. hash shape and expiry ordering); `db:check` clean; applied in staging by the `migrate` job |
| Feature flag | Risky surface off by default | `auth.login` off: API routes, `/login` and `/account` return 404, nav hides "Sign in" (staging E2E). Left **off** in staging: the live widget needs a registered public domain (OD-016) |
| Web | Pages and states | `/login` (widget, loading and error states, "what we store"), `/account` (details, sign out, sign out everywhere); header shows "Sign in" or the user's name; all `noindex` |
| Tests | Suites pass | `pnpm run ci` green: 545 tests (+22 auth unit, +6 repository, +16 auth e2e, +11 redirect); staging E2E auth 5/5 (on) and 1/1 (off), public routes 17/17, smoke 8/8 |
| Findings | Fixed during the phase | (1) Next 16 streams metadata to browsers, so `notFound()` in `generateMetadata` alone gave soft 404s on `/login` (and would have on `/search` without a query); every gated page now also gates in the page body; rule added to UI-UX.md. (2) Critical Next.js advisory GHSA-vcvr-r3jv-pc5j (RCE in `next/og`, not used by us) appeared during the phase: upgraded to 16.3.6 (passes the 7-day release-age policy). (3) The append-only audit table broke a test assumption; the test was scoped to its own entries instead of weakening the table |
| Deferred | Out of scope | Live widget sign-in (needs the public domain, OD-016); Content Security Policy allowing `telegram.org` on `/login` (security-headers phase); RBAC and object-level authorization (PHASE-17) |
